INTRODUCTION                                             *knobby-introduction*

Knobby captures a number under the cursor and assigns it to a physical rotary
encoder. Press an encoder button to capture the number, turn the encoder to
change it, and press the same button anywhere to release it.

Captured ranges use Neovim extmarks, so they follow normal buffer edits. Each
capture is highlighted and, by default, labelled with the encoder number and
increment size. Integer, decimal, and scientific notation are supported using
exact decimal string arithmetic.

==============================================================================
REQUIREMENTS                                             *knobby-requirements*

- Neovim 0.10 or newer.
- Linux/WSL: `amidi` from alsa-utils and an ALSA raw MIDI input.
- macOS: `receivemidi` and a CoreMIDI input.
- Native Windows: `receivemidi.exe` and a Windows MIDI input.

Knobby selects `amidi` on Linux/WSL and ReceiveMIDI on macOS and native
Windows. Install the macOS backend with: >sh

    brew install gbevin/tools/receivemidi
<
On native Windows, download `receivemidi.exe` from
https://github.com/gbevin/ReceiveMIDI/releases and place it on PATH, or set
`midi.command` to its full path. Native Windows does not use USB/IP or ALSA.

A controller connected to Windows can be attached to WSL with usbipd-win; see
the repository README for complete platform setup instructions.

SETUP                                                           *knobby-setup*

Call setup after the plugin has been added to 'runtimepath': >lua

    require("knobby").setup()
<
With lazy.nvim, the `opts` field calls setup automatically: >lua

    {
      "mrsharpoblunto/knobby",
      lazy = false,
      opts = {},
    }
<
The built-in Intech EN16 profile and automatic device discovery are enabled by
default. Use |:KnobbyDevices| and |:checkhealth-knobby| to diagnose a device.

The Grid factory default is an absolute 0-127 encoder. For values that can move
without bounds, configure each encoder's Setup event in Grid Editor for Encoder
Mode 2 (2's Complement), then use: >lua

    require("knobby").setup({
      controller = { profile = "intech_en16" },
    })
<

==============================================================================
CONFIGURATION                                           *knobby-configuration*

The default configuration is equivalent to: >lua

    require("knobby").setup({
      midi = {
        enabled = true,
        backend = "auto",
        command = "auto",
        line_buffered = true,
        port = "auto",
        match = {},
        reconnect = true,
        reconnect_interval_ms = 2000,
      },
      coordination = {
        enabled = true,
        address = "auto",
        scope = "default",
        activation = "focus",
        reconnect_interval_ms = 150,
        broker_timeout_ms = 2000,
      },
      controller = {
        profile = "intech_en16",
        turn_flush_ms = 8,
        button_guard_ms = 25,
        roles = {
          navigation = {
            index = false,
            captured_only = false,
            wrap = true,
          },
          step = {
            index = false,
            reset_on_press = true,
          },
        },
      },
      capture = {
        duplicate = "reject",
        invalid_number = "release",
        undo_join_ms = 250,
      },
      ui = {
        highlight = "KnobbyCapture",
        label_highlight = "KnobbyLabel",
        notifications = true,
        virtual_text = {
          enabled = true,
          position = "inline",
          format = " ⟦E%d ±%s⟧",
        },
      },
      keys = {
        step_down = "[k",
        step_up = "]k",
        step_reset = false,
      },
    })
<
                                                   *knobby-device-selection*
When `midi.port` is "auto", Knobby selects a device only when exactly one raw
MIDI input matches. `midi.backend` selects "amidi" or "receivemidi"; "auto"
uses ReceiveMIDI on macOS and native Windows, and amidi elsewhere.
`midi.command` defaults to `receivemidi.exe` on Windows and the backend name
on other platforms; it can also be an executable path or command list.

`midi.match` accepts `usb_id`, `serial`, `card`, `name`, and `port`. The `name`
is a Lua pattern; other fields match exactly, ignoring case. ALSA exposes all
of these identities. ReceiveMIDI exposes platform MIDI port names, so `name`
and `port` are the useful selectors on macOS and Windows. An explicit port
such as "hw:Grid,0,0", "Grid", or "Grid MIDI" can be used instead.

The profile's device match values are defaults. Values in `midi.match`
override them. For example: >lua

    require("knobby").setup({
      midi = {
        match = {
          usb_id = "303a:8123",
          name = "^Grid",
          serial = "123456",
        },
      },
    })
<
                                                    *knobby-capture-options*
`capture.duplicate` controls what happens when another encoder captures the
same number. "reject" keeps the existing capture; "transfer" moves it.

`capture.invalid_number` controls what happens when edits make a captured range
invalid. "release" removes the capture on its next turn; "keep" retains it.

The default increment is the power of ten represented by the least-significant
displayed digit. Thus 42 uses 1, 42.0 uses 0.1, and 42.750 uses 0.001.

                                                     *knobby-button-guard*
Turns are buffered for `controller.turn_flush_ms`. On button press, a newest
turn inside `controller.button_guard_ms` is discarded and new turns are briefly
suppressed. This prevents a push-induced encoder tick from modifying a value
immediately before capture or release.

MULTIPLE INSTANCES                                  *knobby-multi-instance*

Coordination is enabled by default. Instances with the same
`coordination.scope` elect one local broker. Only the broker opens the MIDI
device, then it forwards messages to the active Neovim over a Unix-domain
socket on Linux/macOS or a named pipe on Windows. Captures remain local to
each instance. A surviving instance becomes broker if the current broker exits.

With `coordination.activation = "focus"`, |FocusGained| activates an instance
and |FocusLost| deactivates it. No instance receives MIDI while focus is in a
shell pane or another application.

For tmux, add this to ~/.tmux.conf: >tmux

    set-option -g focus-events on
<
Reload the configuration or restart/detach and reattach tmux. Confirm the
setting with: >sh

    tmux show-options -gv focus-events
<
It must print "on", and the outer terminal must support focus reporting.

Set `coordination.activation = "manual"` when automatic focus reporting is
unavailable. Use |:KnobbyActivate| to select a recipient and
|:KnobbyDeactivate| to stop routing. |:KnobbyStatus| reports the broker/client
role, active state, connected instance count, and endpoint.

`coordination.address = "auto"` is recommended. The automatic endpoint and
lock names include `coordination.scope`; use separate scopes for independent
controllers or groups. `reconnect_interval_ms` controls client election and
reconnection. `broker_timeout_ms` controls stale-broker takeover.

SPECIAL ENCODER ROLES                              *knobby-special-encoders*

Physical encoders can be reserved for navigation and step adjustment. Both
roles are disabled by default. For example: >lua

    require("knobby").setup({
      controller = {
        roles = {
          navigation = {
            index = 16,
            captured_only = false,
            wrap = true,
          },
          step = {
            index = 15,
            reset_on_press = true,
          },
        },
      },
    })
<
                                                    *knobby-navigation-role*
Turning the navigation encoder forward moves the cursor to the next capturable
number in the current buffer; turning backward moves to the previous one. A
larger relative delta moves across multiple values. Navigation wraps by
default; set `wrap = false` to stop at the first or last value.

Pressing the navigation encoder toggles between all capturable numbers and
only numbers that are currently captured. `captured_only` sets the mode used
at startup. The toggle produces a notification and is included in
|:KnobbyStatus|.

                                                          *knobby-step-role*
Turning the step encoder forward multiplies the step of the captured number
under the cursor by ten. Turning backward divides it by ten. Its button resets
the step from the number's displayed precision when `reset_on_press` is true.

Setting a role's `index` to false disables it. An encoder index cannot be used
by both roles. Role buttons and turns perform their special action instead of
normal MIDI capture or value adjustment.

CONTROLLER PROFILES                                         *knobby-profiles*

All EN16 profiles map channel 1 control-change and note numbers 32 through 47
to encoders 1 through 16. Available profiles are:

intech_en16
        Grid relative Encoder Mode 2 (2's Complement), and the default. Left
        turns send 127 and right turns send 1, with larger deltas possible from
        velocity. Absolute EN16 mode is not supported.

intech_en16_binary_offset
        Grid relative Encoder Mode 1. Left turns send 63 and right turns send
        65.

For contiguous custom controls: >lua

    require("knobby").setup({
      controller = {
        profile = "custom",
        channel = 1,
        controls = {
          count = 8,
          turn = { message = "cc", first_number = 20 },
          press = {
            message = "note",
            first_number = 40,
            minimum_velocity = 1,
          },
          rotary = { encoding = "twos_complement" },
        },
      },
      midi = { match = { name = "^My Controller" } },
    })
<
For noncontiguous controls, make `controls` a list containing `index`, `turn`,
`press`, and `rotary` entries. Built-in rotary encodings are:

- absolute_wrap
- twos_complement
- binary_offset
- sign_magnitude
- inc_dec

`rotary.encoding` may instead be a function receiving `(value, previous_value,
options)` and returning a signed delta.

==============================================================================
COMMANDS                                                     *knobby-commands*

                                                        *:KnobbyToggle*
:KnobbyToggle {encoder}
        Capture the number under the cursor for {encoder}, or release that
        encoder if it already has a capture.

                                                       *:KnobbyRelease*
:KnobbyRelease [encoder]
        Release one encoder, or every capture when [encoder] is omitted.

                                                        *:KnobbyStepUp*
:KnobbyStepUp
        Multiply the step of the capture under the cursor by ten.

                                                      *:KnobbyStepDown*
:KnobbyStepDown
        Divide the step of the capture under the cursor by ten.

                                                     *:KnobbyStepReset*
:KnobbyStepReset
        Reset the step from the number's displayed precision.

                                                        *:KnobbyDevices*
:KnobbyDevices
        Display discovered MIDI inputs and their available identities.

                                                         *:KnobbyStatus*
:KnobbyStatus
        Display the MIDI connection and current captures.

                                                      *:KnobbyReconnect*
:KnobbyReconnect
        Stop the current MIDI reader, discover a device, and reconnect.

                                                         *:KnobbyEnable*
:KnobbyEnable
        Start MIDI discovery and input.

                                                        *:KnobbyDisable*
:KnobbyDisable
        Leave shared MIDI coordination without removing captures. If this was
        the broker, another enabled instance takes ownership. With coordination
        disabled, stop this instance's MIDI reader directly.

                                                       *:KnobbyActivate*
:KnobbyActivate
        Route MIDI events to this Neovim instance.

                                                     *:KnobbyDeactivate*
:KnobbyDeactivate
        Stop routing MIDI events to this Neovim instance.

==============================================================================
MAPPINGS                                                     *knobby-mappings*

The defaults apply only in Normal mode:

                                                        *[k-knobby*
[k      Divide the step of the capture under the cursor by ten.

                                                        *]k-knobby*
]k      Multiply the step of the capture under the cursor by ten.

Counts are supported. For example, `3]k` multiplies the step by 1000.

For custom mappings, disable the corresponding default and map these targets:

                                             *<Plug>(KnobbyStepDown)*
                                             *<Plug>(KnobbyStepUp)*
                                             *<Plug>(KnobbyStepReset)*
>lua

    require("knobby").setup({
      keys = { step_down = false, step_up = false },
    })
    vim.keymap.set("n", "<leader>kd", "<Plug>(KnobbyStepDown)",
      { remap = true })
    vim.keymap.set("n", "<leader>ku", "<Plug>(KnobbyStepUp)",
      { remap = true })
<

STATUS AND HEALTH                                               *knobby-health*

                                                    *:checkhealth-knobby*
:checkhealth knobby
        Check the Neovim version, platform MIDI backend, controller profile,
        discovery, and connection state. ALSA permissions and device access
        are also checked when using amidi. On Windows, missing ReceiveMIDI
        guidance points to its release downloads.

`require("knobby").statusline()` returns a compact connection and capture
summary suitable for a statusline component. A ▶ routing marker means this
instance is active; · means it is inactive.
